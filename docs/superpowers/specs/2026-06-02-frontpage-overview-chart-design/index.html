Frontpage 30-Day Overview Chart — Design

Date: 2026-06-02

Goal

Add a chart to the frontpage showing the last 30 days of streams so a viewer can gauge how much money TheQuartering earns per hour streamed. Plots time streamed, messages, and rant earnings per stream, plus an explicit $/hour line.

Decisions

  • X-axis granularity: per stream (one point per stream, at its date). Days with multiple streams get multiple points.
  • Money-per-hour: explicit derived $/hour line, not left to visual inference.
  • Chart form: multi-axis combo — bar for rant $ earned, lines for the rest.
  • Default visible: rant $ (bar) + $/hour (line) ON; messages + hours OFF, toggleable.
  • Window: last 30 days anchored to the most recent stream's date (always populated regardless of streaming gaps), not rolling-from-today.

Data (build time, in index.page.tsx)

The index page already loads all streams via search.pages("url^=/streams/"). No data-pipeline change.

  1. Find anchor = max data.meta.started_at across streams.

  2. Keep streams with started_at >= anchor - 30 days.

  3. Sort ascending by started_at.

  4. Per stream, compute a point:

    fieldsource
    datemeta.started_at (ISO)
    titlemeta.title
    rantUsdstats.totals.rant_total_cents / 100
    hoursmeta.duration_seconds / 3600
    msgsstats.totals.messages
    usdPerHourhours > 0 ? rantUsd / hours : 0

  5. Serialize the array (~30 × 6 fields) into <script type="application/json" id="overview-data">…</script>.

Mounting

  • Add <div id="island-overview-chart"> with a lightweight placeholder at the top of the frontpage, above the grouped stream list, in a bordered card matching existing card style.
  • index.page.tsx returns a fragment that also emits <script type="module" src={url("/app/main.js")}> so the JS bundle loads only on the frontpage. base.tsx stays untouched; the faq page stays lean.
  • Extend app/main.jsx: if #island-overview-chart exists, read + parse #overview-data, lazy-import OverviewChart, and createRoot(...).render. Mirrors the existing #island-stats-chart-echarts mount path.

New component: app/components/OverviewChart.tsx

  • ECharts combo using the same echarts/core registration approach as StatsEcharts.tsx, adding BarChart alongside LineChart (GridComponent, TooltipComponent, LegendComponent, CanvasRenderer).
  • X-axis: category, one entry per stream, labeled by date. Multiple same-day streams appear as adjacent points.
  • Series:
    • rant $ — bar — visible by default — dollar y-axis (left).
    • $/hour — line — visible by default — dollar y-axis (left, shared; both are dollar-scaled and comparable in magnitude).
    • messages — line — hidden by default — own y-axis.
    • hours — line — hidden by default — own y-axis.
  • Y-axes: left dollar axis always shown. Messages and hours axes are shown only when their series is toggled on (avoid empty axis clutter).
  • Toggle UI: button row mirroring StatsEcharts.tsx toggle pattern.
  • Tooltip: stream title + date header, then all four metric values (formatted: $ with 2 decimals, hours, msgs count, $/hour).

Types

Add a Point (or OverviewPoint) type. Inline in the component is fine, or in app/types/stats.ts if it aids reuse. Reuses existing StatsJson for the build-time computation.

Out of scope (YAGNI)

  • Per-day aggregation (decided per stream).
  • Date-range picker / configurable window.
  • Server-side chart rendering (keep the client-island pattern).
  • Touching the streams-data pipeline or toClientData.

Testing / verification

  • deno task build succeeds; frontpage renders the card.
  • deno task dev:quality (type check + fmt) passes.
  • Manual: serve, confirm chart shows rant $ bars + $/hour line by default, toggles reveal messages/hours with their axes, tooltip shows all four values, dark mode and fullscreen behave (match StatsEcharts conventions).
